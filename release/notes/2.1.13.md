## 2.1.13 (2026-10-21)

This update fixes security problems and bugs in GpgFrontend 2.1, and adds
a few small improvements. Everyone who stays on 2.1, including Qt5 users,
should update.

### Security fixes

- **Your files are never half-written.** Encrypted, decrypted, signed and
  archive output is first written to a hidden temporary file. It replaces
  the target only after the whole operation has worked. A failed operation
  leaves the original file untouched.
- **Unprotected decrypted content is withheld.** If a message has no
  protection against changes, its decrypted content is no longer shown or
  saved. This also applies to password-only (symmetric) messages.
- **Extracting archives is safer.** An archive can no longer place files
  outside the target folder, use links that point outside it, unpack huge
  amounts of data, or give files special permissions.
- **Secrets are wiped from memory.** Passphrases and other sensitive data
  are erased after use, also in the user interface. Generated passphrases
  are now evenly random.
- **Stricter checks** for names, comments and email addresses in user IDs.

### What's new

- **A friendlier key list.** You can find a key by its fingerprint in any
  view, even when you paste it with spaces, colons or in another case. Key
  trees are expanded by default, and the signer and recipient pickers stay
  usable while the key list refreshes.
- **Clearer encryption errors.** When a key cannot be used to encrypt,
  GpgFrontend tells you why (revoked, expired, disabled, or no usable
  encryption subkey) and which recipient it is about.
- **Text editor settings.** Choose the editor's font and tab size in the
  appearance settings. Changes apply without a restart.
- **Smaller touches.** A confirmation after a successful key export, subkey
  dates with tooltips, the subkey's own expiry date when you edit a
  subkey, and better text search in the editor.

### Other fixes

- If a message decrypts correctly but you do not have the signer's public
  key, you still get your decrypted text or file, with a warning.
- Several crashes are fixed: when importing keys, with an empty subkey
  list, when a key disappears while its details are open, and when a
  signature reference is missing.
- The app no longer hangs when it quits or restarts.
- Unsaved editor text and its line endings are kept more reliably when the
  app closes and recovers.
- Key generation windows stay open when generation fails, so you do not
  lose what you entered.
- Wrong key database settings now show an error instead of failing
  silently.
- Modules are found again when the AppImage runs unpacked (without FUSE).
- Window sizes and positions are restored more safely, and the native
  macOS colours are kept.
- Translations were updated for all interface changes.

### Downloads

- The Windows packages include GnuPG 2.5.21 (up from 2.5.18).
