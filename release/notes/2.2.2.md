## 2.2.2 (2026-08-10)

This update adds profiles, new key and smart card features, and many
security fixes for the built-in rPGP engine. Everyone using 2.2 should
update. Your key databases and settings from 2.2.1 are moved over
automatically.

### Security fixes

- **Choose how the app's own key is protected.** GpgFrontend uses this key
  to protect the data it stores. You can leave it unprotected, keep it in
  the system keychain (macOS Keychain, Windows Credential Manager, or
  libsecret on Linux), or protect it with a PIN. You can change the PIN,
  and reset it if you forget it.
- **Forged key information is rejected (rPGP).** Revocations, expiry dates
  and what a key may be used for are only accepted when the key's own
  signature on them is valid. A forged revocation can no longer be
  attached to a key.
- **Weak and harmful input is refused (rPGP).** The old MD5, SHA-1 and
  RIPEMD-160 hash algorithms are never accepted as valid. Messages without
  protection against changes are refused before decryption. Small files
  that unpack into huge amounts of data are limited.
- **Weak key types are gone (rPGP).** RSA keys shorter than 2048 bits and
  DSA keys can no longer be created. Existing keys keep working, and
  GnuPG is not affected.
- **Extracting archives is safer,** and user IDs are checked more strictly.

### What's new

- **Profiles.** Keep several separate setups, each with its own key
  databases, settings and protection key. Switch between them from the new
  Profiles menu.
- **Portable profile packages.** Save a whole profile into one
  passphrase-protected file (`.gfp`) and open it anywhere with a
  double-click. It runs as a temporary profile that leaves nothing behind,
  and asks when you close it whether to save your changes into the file.
- **Hide messages in chat.** Encrypt and sign a message into a single
  word of letters and digits that survives being pasted into any chat app.
  With a phrase you share with your contact, it looks like random text to
  anyone who does not have the same phrase. The phrase is stored encrypted
  and can be generated in the settings.
- **Key categories and a better key list.** Coloured category tabs that
  you can reorder replace the old favourites list. The key list gets
  columns for status and expiry date, a warning before keys expire, search
  and sorting. It remembers column widths and ticked keys after a restart.
- **More control over keys.** Change the passphrase of a single subkey,
  choose which encryption subkey is used for a recipient, export keys to a
  place you choose, search a key server for the selected key, and see
  whether a key is version 4, 5 or 6.
- **Move a key to a smart card.**
- **A refreshed interface.** Settings have a searchable sidebar with new
  pages for rPGP and advanced options. The file browser shows the current
  path as clickable parts and marks OpenPGP files. The module manager was
  redesigned, appearance changes apply at once, and the setup wizard can
  switch language right away.
- **GnuPG maintenance in settings:** clear the password cache, reload the
  configuration, and restart gpg-agent.
- **rPGP: set when a key expires.**

### Other fixes

- rPGP: fixes for version 6 messages, expiry dates, revoked keys and
  showing who signed. These were tested against GnuPG and another OpenPGP
  program.
- GnuPG: after a failed connection, GpgFrontend waits before trying again
  instead of retrying on every operation. A GnuPG home folder path that is
  too long gives a clear error. If GnuPG's `gpgconf` is missing, the app
  uses rPGP instead of refusing to start.
- GnuPG: real error messages replace general ones, and smart card serial
  numbers are checked correctly.

### Before you update

- **AppImage and Windows users: pick the right download.** The portable
  version is now a separate download. Choose the file with `portable` in
  its name for the portable version, or any other one for the normal
  version. The `ENV.ini` file that used to turn on portable mode no longer
  does anything.
